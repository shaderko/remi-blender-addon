# Remi 2.7.0-beta.18 — Responsive sync with large mesh queues

Large mesh transfers no longer share the control loop used for board movements,
project selection and WebSocket updates. Previously, restoring a project could
wait for every file to download before marking its board ready; a slow or failed
file could make synchronization appear frozen again after restarting Blender.

- Board metadata and the live subscription connect before downloading files.
  Unavailable assets show a downloading state while other cards remain usable.
- Local cards stay usable immediately. Every queued upload announces its card
  before file transfer, so other devices show **Uploading** placeholders in the
  same project. Positions synchronize before the file arrives; completion uses
  the same card identity. Failed uploads remain visible, and deleted placeholders
  cannot be resurrected by a late transfer.
- Uploads and downloads run separately from control messages, with one active
  transfer at a time. Project switches and card movements take priority over a
  backlog of large mesh uploads, including movement of an uploading card.
- Each transfer has an independent authenticated session fixed to its original
  project. Switching projects cannot attach a pending mesh to a different board.
- File uploads have a five-minute transport timeout; small API requests retain
  their shorter timeout. SHA-256/size checks and idempotency receipts remain.
- Pending uploads survive restart. Failed upload messages also survive restart;
  oversized meshes report the 100 MiB limit without blocking other controls.
  Temporary upload copies are removed without deleting local source assets.
- Missing cached files can redownload. Remote download completion preserves local
  edits, and receipts remain hidden until a fresh metadata snapshot is available.

Includes beta.17's Gaussian editing, safe Cloud Gaussian loading, IDOL HTTPS
redirect fix and corrected vertical Alt-orbit.

Requires Blender 5.3. Install the matching operating-system ZIP through
Preferences → Get Extensions → Install from Disk, then restart Blender. Existing
outbox commands and local asset files are retained; do not regenerate the models.
SHA-256 checksums accompany the Windows x64 and macOS arm64 packages.

Regression coverage restores nine queued meshes, stalls an upload/download, and
verifies live readiness, same-card movement, project selection, project-bound
attachment, durable upload receipts, oversized-file errors and restart recovery.
Blender checks cover downloading placeholders, new file revisions and local edit
preservation. SDK WebSocket integration tests and platform package/installation
checks run before publication. This reproduces the client failure mode; it does
not establish the affected Windows account's current storage usage.

Shared uploading placeholders require the matching Cloud update and its
`cloud_board_upload` migration. Older servers remain compatible with file sync;
they simply cannot display remote placeholders until upgraded.
