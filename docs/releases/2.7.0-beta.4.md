# 2.7.0-beta.4 — compiled parallel octree tracing

- Replace the production octree tracer's Python/NumPy hot path with an optional
  compiled Numba CPU implementation. Up to eight threads trace independent rays
  in 32K batches against a shared, read-only, stackless octree.
- Keep the density threshold, complete Gaussian supports, step budget, ten
  bisections, and color/gradient-normal formulas. Use float64 without fast-math;
  do not reduce texture resolution or cap nearby Gaussian candidates for speed.
- Bound tracer scratch to 128 MiB. Preserve cancellation and report exhausted
  rays as missing evidence, not hits.
- Show rays/sec and CPU backend/thread count. The counter is UV rays, not steps.
- Reuse the external Python's optional Numba installation; no package installs
  or downloads happen automatically. Retain an explicitly reported NumPy fallback.
- Use the same canonical module name in workers/tests so Numba caches remain
  loadable across processes. Caches are generated locally, never shipped.

The captured local 1K bake (262,144 Gaussians, 593,983 rays, 128 steps/ray) finished
in 17.9 seconds wall time. Sample flags matched the reference; tiny numerical map
differences remain possible. This is not a general speed or geometry-quality guarantee.

See [parallel tracing and benchmarks](../texture_projection.md#parallel-tracing-and-speed).
